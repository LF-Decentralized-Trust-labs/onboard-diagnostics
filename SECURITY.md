# Security Policy

Security reports are welcome and should be handled privately first.

## Supported Versions

This project is pre-1.0. Security fixes target the default branch and the latest published package version once packages are released.

## Reporting a Vulnerability

Do not open a public GitHub issue for a security vulnerability.

Report security concerns through the LF Decentralized Trust / Hyperledger HackerOne program:

https://hackerone.com/hyperledger?type=team

Include:

- the affected command, script, package, or workflow
- steps to reproduce
- expected impact
- any safe proof of concept or logs
- whether the issue is already public

## What to Expect

Maintainers will triage reports as quickly as practical, coordinate fixes privately when needed, and publish remediation details after users have a reasonable path to upgrade or mitigate.

## Scope

Security-sensitive areas include the CLI, shell scripts, package metadata, dependency handling, generated reports, and any future distribution workflow.
